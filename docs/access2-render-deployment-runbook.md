# ACCESS2 Render Deployment Runbook

## Purpose

Use this runbook to deploy the current ACCESS2 V1 demo/staging stack to Render without changing product behavior. The Render deployment keeps the same V1 path:

login -> patient/worklist -> intervention/outcome evidence -> review packet -> approval -> audit bundle export -> verification

Do not use this demo/staging setup as a PHI production environment without a separate security, compliance, and operations review.

## Services

The repository includes a root `render.yaml` blueprint with four Render resources:

- `access2-postgres`: managed Render Postgres.
- `access2-redis`: Render Key Value/Redis-compatible service.
- `access2-backend`: FastAPI web service with `rootDir: backend`.
- `access2-frontend`: Next.js web service with `rootDir: frontend`.

## Backend

Backend details confirmed from the repo:

- App import path: `app.main:app`.
- Build command: `pip install --upgrade pip && pip install -e .`.
- Start command: `bash scripts/render-start.sh`.
- The start script runs `alembic -c alembic.ini upgrade head` before starting Uvicorn.
- Uvicorn binds to `0.0.0.0` and uses Render's `$PORT`.
- Health check path: `/api/v1/health/live`.
- Readiness check path: `/api/v1/health/ready`.

Backend environment variables:

- `DATABASE_URL`: from Render Postgres `connectionString`.
- `REDIS_URL`: from Render Key Value `connectionString`.
- `SECRET_KEY`: generated by Render for the backend service.
- `JWT_ALGORITHM`: `HS256`.
- `ACCESS_TOKEN_EXPIRE_MINUTES`: `60`.
- `ENVIRONMENT`: `production`.
- `DEBUG`: `false`.
- `FRONTEND_ORIGIN`: set after the frontend service URL is known, for example `https://access2-frontend.onrender.com`.

Render Postgres may provide `DATABASE_URL` as `postgresql://...`; the backend normalizes that to the SQLAlchemy psycopg driver URL at startup.

## Frontend

Frontend details confirmed from the repo:

- Build command: `npm ci && npm run build`.
- Start command: `npm run start -- -H 0.0.0.0 -p $PORT`.
- Local package scripts remain unchanged.
- The frontend reads the backend API base URL from `NEXT_PUBLIC_API_BASE_URL`.

Frontend environment variables:

- `NODE_ENV`: `production`.
- `NEXT_PUBLIC_API_BASE_URL`: set after the backend service URL is known, for example `https://access2-backend.onrender.com/api/v1`.

Do not set Render production environment variables to local URLs such as `localhost:8000` or `localhost:3000`.

## Deployment Steps

1. Create a Render Blueprint from the repository root.
2. Let Render create the Postgres, Key Value, backend, and frontend resources from `render.yaml`.
3. After Render assigns service URLs, set:
   - backend `FRONTEND_ORIGIN` to the frontend service URL.
   - frontend `NEXT_PUBLIC_API_BASE_URL` to the backend service URL plus `/api/v1`.
4. Redeploy both web services after setting those cross-service URLs.
5. Confirm the backend deploy log shows Alembic migrations running before Uvicorn starts.

## Smoke Test

Run these checks against the deployed URLs:

1. Backend live health returns HTTP 200:
   - `https://<backend-service>.onrender.com/api/v1/health/live`
2. Backend readiness returns HTTP 200 after Postgres and Redis are reachable:
   - `https://<backend-service>.onrender.com/api/v1/health/ready`
3. Frontend login loads:
   - `https://<frontend-service>.onrender.com/login`
4. Login succeeds only when the deployed database has a seeded user.
5. The ACCESS2 V1 demo path requires seeded/demo data, a persisted review packet snapshot, and an approved export-ready snapshot before bundle download and verification can be demonstrated.

## Troubleshooting

- If `/health/live` fails, check backend build/start logs and confirm the `app.main:app` start command is running.
- If `/health/ready` fails, check `DATABASE_URL`, `REDIS_URL`, migrations, and Render resource status.
- If the frontend loads but login fails with `Unable to sign in right now. Please try again.`, confirm `NEXT_PUBLIC_API_BASE_URL` points to the deployed backend `/api/v1` URL and backend health is passing.
- If browser requests are blocked by CORS, confirm backend `FRONTEND_ORIGIN` exactly matches the deployed frontend origin.
- If demo pages load but audit-readiness or bundle actions are empty, seed or recreate demo data through the documented ACCESS2 local/operator paths before presenting the full V1 demo.

## Commit Hygiene

Commit only intentional source, deployment, and documentation changes. Do not commit:

- `frontend/.env.local`
- `frontend/tsconfig.tsbuildinfo`
- `backend/.tmp/pytest_cache`
- local secrets or Render-generated values
